# Briefs

One brief per sub-project. A brief states **what** is being built and **why**,
in terms a non-developer can check, and names the boundaries: what is in
scope, what is explicitly out, and what must be true before work starts.

A brief is written before its spec. It is the place where scope is argued
about; once agreed, the spec turns it into a design and the plan turns
that into steps.
